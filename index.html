Your honeypot feeds are blind to MCP

Take every host that behaves like an MCP catch-all tarpit — it returns a tool list for any request, real or nonsense — and check it against the honeypot tag the big scan databases already ship. // method

How to tell real from fake

Four explainable signals, no black box. A host that completes a real handshake is genuine by definition and scores zero — a legitimately replicated fleet is never mistaken for a campaign.

DECOY-TARPITcatch-all behaviour

returns a tool list for a tool or method it cannot possibly implement.

DECOY-FINGERPRINT-REUSEcross-network reuse

one response fingerprint replicated across many IPs and 3+ networks.

DECOY-UNVERIFIED-BANNERbanner without a handshake

advertises MCP but never completes a real initialize + tools/list.

DECOY-APPLIANCEincoherent appliance

claims to be an MCP server and a VPN / router / camera at once.

// scale

The deception is coordinated

Grouping the MCP-advertising surface by response fingerprint reveals deployments, not lone hosts: 343 clusters over 99,082 hosts, and 40 cross-network spoof campaigns — one fabricated banner sprayed across three or more networks with no real server among them. The single largest is one fingerprint across 82,969 IPs in 25 countries — a mass banner-spoof, not 83,000 servers.
